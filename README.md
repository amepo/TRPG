# 灯火のテーブル

ブラウザだけで遊べる **d20 系 TRPG**。ビルド不要・実行時の依存パッケージゼロ・**完全オフライン**。
データはすべて端末内（localStorage）で処理され、サーバーには何も送信されません。

**2つの世界観**を収録しています。シナリオを選ぶと世界が切り替わり、クラス・装備・敵・技能・配色、
そして固有ルールまで丸ごと入れ替わります。

| 世界観 | 内容 |
| --- | --- |
| 🕯️ **灯火のテーブル** | 剣と魔法のファンタジー。種族6／クラス5／技能18／呪文16／モンスター16 |
| 🌃 **ネオンの雨** | 企業に支配された街。出自6／役割5／技能18／プログラム16／敵15。**サイバーウェア**と**ネットラン**が加わる |

```bash
npm start          # → http://localhost:5173/
```

> ES Modules を使っているため、`index.html` をダブルクリックして `file://` で開くと動きません。
> 上記のローカルサーバー（依存なしの Node 製、`tools/serve.js`）経由で開いてください。

スマホでは **ホーム画面に追加**すると全画面で起動し、オフラインでも全機能が使えます。

## 3つのモード

| モード | できること |
| --- | --- |
| **ソロプレイ** | シナリオを選び、一人で最初から最後まで遊ぶ。判定も戦闘も自動処理。 |
| **セッション支援** | 対面／オンラインの卓で使う道具。ダイス、キャラクターシート、イニシアチブ表。世界観は画面上部で切り替えます。 |
| **シナリオ工房** | 自分の物語を書く。判定・戦闘・分岐・複数エンディング。書いたものはそのまま遊べる。 |

## サイバーパンク固有のルール

**サイバーウェア（適合度）** — 改造は強いが、体が受け入れる量には上限があります（`3 ＋ 耐性修正 ＋ レベル/2`）。
超過したぶんだけ、**すべての判定・セーヴ・攻撃に固定のペナルティ**がつきます。
「もう一つ入れるか、抑えるか」を毎回選ばせるための仕組みです。

**ネットラン（電脳侵入）** — 防壁を層ごとに抜けていくミニゲーム。毎層、抜け方を選びます。

| 手 | 判定 | 痕跡 |
| --- | --- | --- |
| 慎重に潜る | 有利 | 成否にかかわらず +1 |
| 一気に押し通る | 通常 | 成功 0／失敗 +2 |
| 迂回路を探す | DC +3 | 成功 0／失敗 +2 |
| 強引に焼き切る | 自動成功 | +3、さらに反動ダメージ |

痕跡が上限に達すると逆探知され、ICE との戦闘か、そのまま弾き出されます。

## ルール（d20 系）

- **能力値6種**（筋力・敏捷・耐久・知力・判断・魅力）、修正値は `floor((値−10)/2)`
- 武器・防具・敵の数値は **SRD 5.1** を基準に合わせています（下記）
- **判定**：`1d20 ＋ 能力修正 ＋ 習熟ボーナス` が DC 以上で成功。ナチュラル20は自動成功＋ダメージダイス倍、ナチュラル1は自動失敗
- **有利／不利**：2d20 の高い方／低い方。両方あると打ち消し合う
- **習熟ボーナス**：レベル1〜4で +2、以降4レベルごとに +1（最大10レベル）
- **戦闘**：イニシアチブ順のターン制。攻撃ロール vs AC、状態異常、死亡セーヴ（3回成功で安定／3回失敗で死亡）
- **休憩**：小休憩でヒットダイス消費＋能力回復、長休憩で全快
- 能力値の id は世界共通（`str/dex/con/int/wis/cha`）。呼び名だけが世界ごとに変わります

## ダイス式

`1d20` `2d6+3` `4d6kh3`（高い方3つ）`2d20kl1`（不利）`1d10!`（振り足し）`1d8+1d6-2`

## シナリオの形式

シナリオは素の JSON（プレーンオブジェクト）です。工房で書き出したファイルをそのまま共有できます。

```js
{
  id: 'my-scenario', title: 'タイトル', world: 'embers', start: 'nodeA',
  vars: { trust: 0 },
  nodes: {
    nodeA: {
      title: '場面の見出し', art: '🌫️',
      text: ['本文。{name} で先頭の名前が入る。'],
      onEnter: [{ setFlag: 'met' }, { var: 'trust', add: 1 }],
      choices: [
        { text: '進む', to: 'nodeB' },
        { text: '調べる', check: {
            skill: 'investigation', dc: 12,
            success: { text: ['見つけた。'], to: 'nodeB', effects: [{ giveItem: 'potion' }] },
            fail:    { text: ['何も出てこない。'], to: 'nodeB' },
        } },
        { text: '鍵を使う', requires: { has: 'ironKey' }, lockedText: '鍵がない', to: 'nodeC' },
      ],
    },
    nodeB: {
      title: '戦闘',
      combat: { enemies: ['goblin', 'goblin'], onVictory: { to: 'nodeC' } },
    },
    nodeC: { title: '結末', ending: { type: 'good', title: '生還', text: ['帰り道は静かだった。'] } },
  },
}
```

**条件**：`{flag}` `{noFlag}` `{var,gte|lte|eq}` `{has}` `{classIn}` `{skillIn}` `{alive}` `{levelAtLeast}` `{all|any|not}`
**効果**：`{setFlag}` `{clearFlag}` `{var,add|set}` `{giveItem}` `{takeItem}` `{gold}` `{xp}` `{damage}` `{heal}` `{rest}` `{log}`

`world` はそのシナリオが属する世界観の id（`embers` または `neon`）。省略すると `embers` です。
シナリオを開始すると、その世界が有効になります。**技能の id は世界ごとに違う**ので、
`netops`（電脳）はネオンにしか、`arcana`（魔法学）はファンタジーにしか存在しません。

ネオンの世界では、戦闘のかわりに**侵入**を置けます。

```js
netrun: {
  title: '社内網', traceMax: 6,
  layers: [
    { name: '外周ファイアウォール', skill: 'netops', dc: 12 },
    { name: '認証ゲート', skill: 'tech', dc: 13, onFail: { damage: '1d6' } },
    { name: '保管区画', skill: 'netops', dc: 14, effects: [{ setFlag: 'gotFiles' }] },
  ],
  ice: ['ice'],                       // 逆探知されたときに出てくる相手
  onSuccess: { to: 'node-a' }, onTraced: { to: 'node-b' },
}
```

## 収録シナリオ

**🕯️ 灯火のテーブル（ファンタジー）**
- **はじめての依頼**（10〜15分）— 導入編。10場面／戦闘1／判定3／結末3。操作を覚えるための小さな仕事
- **鐘の鳴らない村**（40〜60分）— 探索もの。29場面／戦闘4／判定23／結末5。
  村の聞き込みから儀式の阻止まで
- **潮の骨**（30〜45分）— 時間もの。18場面／戦闘1／判定13／結末4。
  大干潮の三時間だけ現れる沈没船へ。潮位が上がりきると船内は水に沈む
- **三つの峠**（30〜45分）— 道行きもの。15場面／戦闘2／判定7／結末4。
  熱病の薬を雪が閉じる前に山向こうへ。峠は三つ、通れるのは二区間ぶん

**🌃 ネオンの雨（サイバーパンク）**
- **初日の運び屋**（10〜15分）— 導入編。13場面／戦闘2／侵入1／判定8／結末4。
  判定・戦闘・ネットラン・改造を一度ずつ通る
- **雨の領収書**（40〜60分）— 探索もの。35場面／戦闘5／侵入1／判定23／結末6。
  消えた弟を追って企業タワーの37階へ。侵入経路は「社員証」「潜入」「ネットラン」の3通り
- **三分間の停電**（30〜45分）— 強盗もの。22場面／戦闘2／判定18／結末5。毎週火曜の停電三分で金庫室へ。
  下見を重ねるほど本番の持ち時間が増える、時間が敵のシナリオ
- **硝子の果樹園**（30〜45分）— 調査もの。27場面／戦闘2／侵入1／判定19／結末8。
  企業の垂直農場で死んだ四人。集めた証拠の量と、気づかれた度合いで結末が変わる
- **最終便**（30〜45分）— 逃走・護衛もの。23場面／戦闘5／判定13／結末6。証人を朝までに街の外へ。
  経路3つ、追跡度と証人との信頼で終わり方が変わる

## 構成

```
index.html                     画面の骨組み
manifest.webmanifest / sw.js   PWA（ホーム画面に追加・オフライン動作）
css/trpg.css                   見た目（ダーク、モバイル優先）
js/worlds/                     世界観（純粋なデータ。エンジンは中身を知らない）
  index.js                     レジストリ。useWorld() で切り替え、購読側が追従する
  fantasy.js                   剣と魔法
  neon.js                      サイバーパンク（サイバーウェア込み）
js/core/                       ゲームロジック（DOM に触れない・Node でテストできる）
  rng.js                       シード付き乱数（同じ種なら同じ展開を再現）
  dice.js                      ダイス式の解析と判定
  rules.js                     d20 ルール（判定・攻撃・ダメージ・状態・休憩・成長）
  traits.js                    特性の定義とフック（世界は id を書き、効果はここに一箇所）
  content.js                   有効な世界観への live view（let 束縛で追従する）
  lore.js                      読み物（地名・勢力・人物・ランダム表）への live view
  character.js                 キャラクター生成と派生値
  combat.js                    ターン制戦闘と敵AI
  augment.js                   サイバーウェアと適合度
  netrun.js                    電脳侵入の状態機械
  scenario.js                  シナリオ形式・条件・効果・点検
  engine.js                    ソロプレイの進行（セーブ／ロード込み）
  store.js                     localStorage 保存
js/ui/                         画面（DOM のみ）
js/scenarios/                  収録シナリオ
tools/                         ローカルサーバー、配信ビルド、アイコン生成、ブラウザ検証
```

ゲームロジックは DOM も `Math.random` も直接触らず、乱数はシード付き `Rng` を経由します。
同じ種なら同じ展開を再現でき、Node のテストから素で動かせます。

世界観は純粋なデータで、エンジン側は「何が存在するか」を知りません。
`js/worlds/` に同じ形のオブジェクトを作って `register()` に渡せば、
第三の世界観（宇宙、和風、ホラー……）をルールごと追加できます。

## 特性

種族や敵が持つ「特性」は、**表示文と効果を分けて**書きます。

```js
traits: [{ id: 'pack', text: '連携射撃：仲間が生きているあいだ攻撃に有利' }]
```

`text` は世界の言葉で自由に。`id` が実際の効果を指します。狼の「群れ戦術」と
企業警備兵の「連携射撃」は名前が違うだけで、同じ `pack` です。
効果の実体は `js/core/traits.js` に一箇所だけ置かれます。

これは実際に踏んだ穴への対処です。以前は `t.includes('群れ戦術')` という
日本語の文字列照合で実装されていたため、同じ効果を別名で呼んだ敵では
**黙って効かなくなっていました**。

```bash
npm run traits          # 宣言と実装の対応表。実装漏れがあれば終了コード1
```

種類は4つ。`passive`（作成時に数値へ畳み込む）、`combat`（戦闘中のフック）、
`active`（戦闘の行動として選べる）、`flavor`（描写のみ）。
`flavor` はキャラクターシートに「（描写）」と明記されます——
**ルールのように読めて実は効かない文を残さない**ための区別です。

## 世界の読み物

各世界は `lore` を持ちます。数値を持たない層で、ルールには一切関わりません。

| 中身 | 使いどころ |
| --- | --- |
| `primer` | その世界がどういう場所か。数段落 |
| `districts` | 区画。空気・物価・縄張り・入る条件 |
| `truths` | 世界の決まりごと。**何ができないか**を先に決める |
| `standing` | 立場の段位（読み物のみ。数値としては誰も読まない） |
| `calendar` | 暦と四季。一年の長さ、月の名前、季節ごとに何が起きるか |
| 種族の `life` | 成人・平均寿命・最長と、その長さが暮らしに何をもたらすか |
| `timeline` | ここまでの経緯。日付より「何が変わったか」 |
| `economy` | 物価の基準。報酬の数字が何を意味するか |
| `places` / `factions` / `figures` | 土地・勢力・顔ぶれ。勢力には `stance`（誰と噛み合っていないか） |
| `names` | NPC 名の生成。キャラクター作成の「おまかせ」もここを引く |
| `tables` | 卓で振れる表（噂・道中・依頼・失敗の余波…）各8〜12項目 |

ホームの「🌍 世界」、またはセッション支援の「🌍 世界」タブから読めます。
表は押すとその場で振れます。

## 設定だけのもの

世界には、**書いてあるが仕組みにはしていない**ものがあります。意図的な線引きで、
どれも世界データのコメントに理由が残してあります。

| | なぜ仕組みにしないか |
| --- | --- |
| 信用スコア（5段位） | 遊ぶ側が管理する項目が増えて卓が重くなる。街の手触りを出すのにそこまでは要らない |
| VR社会 | 電脳を「住める場所」として書くと、盗むか消すために入る倉庫という今のネットランの土台から作り直しになる |
| AI司法 | 判定にも戦闘にも噛まない。噂表から拾える形にだけしてある |

特性の `flavor` と同じ考え方です。**ルールのように読めて実は効かない文を残さない**ために、
「効かないもの」は効かないと分かる場所に置きます。

## 経済

装備・道具・改造にはすべて値段があり、初期資金は世界が決めます
（銀貨25枚 / €$600）。改造は費用を引いてから入ります。

設定に書いた物価と、シナリオが実際に動かす金額は噛み合っていないと意味がないので、
そこは測ります。

```bash
npm run economy         # 物価と報酬の突き合わせ。食い違えば終了コード1
```

見ているもの:

- 買えるものに値段がついているか
- 初期資金で最低限の装備が買えるか
- シナリオの報酬が、宣言した物価の尺度の内側にあるか
- **報酬を約束した結末が、実際に払っているか**（実際に90回遊んで懐の増減を測る）

最後の一つは実際に効きました。「報酬は満額」と書きながら1枚も払わない結末が
4本のシナリオにあり、目視ではひとつも気づけていませんでした。
払わないことに意味がある結末（名乗らずに去る、受け取らない）は
`ending.noPay: true` と宣言します。

## シナリオ工房

書いたものが押し間違いで消えないようにしてあります（20場面まで書いた人が
操作ミスで半分失った、という報告を受けての作り）。

- **自動保存**。触るたびに保存されるので、「保存」を押し忘れても残ります。
  「一覧へ」も「新しく作る」も、いまの分を書き出してから移ります
- **元に戻す**。場面や選択肢の削除、戦闘・結末の切り替えは40手前まで戻せます。
  本文の打ち込みは、打ち始めの姿ひとつにまとめて積みます（一文字ずつ戻っても困るので）

書けるもの:

| | |
| --- | --- |
| 場面 | 見出し・絵文字・本文・**入ったときの効果**（毎回はたらくかも選べる） |
| 選択肢 | 文・行き先・一度きり・判定（技能/DC/成否の行き先と描写と**効果**） |
| | **選んだときの効果**・**見せる条件**（`if`）・**開く条件**（`requires`）|
| 戦闘 | 題・敵の顔ぶれ（難度の目安つき） |
| 結末 | 種類・題・本文 |
| 全体 | タイトル・あらすじ・世界観・**変数**・**自作の敵** |

効果は変数・印・所持金・持ち物・ダメージ・回復・休憩・経験点・ログの9種類、
条件は印・変数・持ち物・技能の4種類。**収録シナリオが使っている効果はすべて
工房でも書ける**ことをテストで固定しています（書けないものが増えたら落ちます）。

**自作の敵**は、世界の敵で足りないときに作れます。名前・種類・手ごわさ（CR を
選べば経験点が決まる）・体力・AC・移動・動き方・攻撃・一言。作った敵は戦闘の
「敵を追加」の先頭に出て、同じ敵を並べればＡＢＣが振られます。点検は、攻撃の
ない敵（戦闘が終わらない）と体力0の敵を間違いとして止め、どこにも出てこない敵は
警告にします。

まだ工房で書けないのは、ネットランと、シナリオ独自のアイテムの定義です。
そこは JSON で書いて読み込んでください。

JSON で書きたいときは、**工房の「見本から始める」から落とせます**。
「開く」でそのまま編集に入るか、「.json」で手元に保存して好きな編集器で書くか。
中身はアプリに埋め込んであるので、オフラインでも落とせます。

```bash
npm run new -- my-scenario --shape=hub --world=neon --title="題名"          # js を作る
npm run new -- my-scenario --shape=hub --world=neon --title="題名" --json   # json を作る
```

## 群れの出し方

群れは**一体で体力の多い塊にせず、頭数で出します**。

```js
enemies: ['direRat', 'direRat', 'direRat', 'direRat']   // 大鼠Ａ〜Ｄ になる
```

どれから倒すか選べることと、倒すたびに向こうの手数が減っていく手応えが、
群れと戦う面白さだからです（遊んだ人からの指摘で直しました。以前は
HP24 の「鼠の群れ」1体でした）。

一体にまとめてよいのは、**個体を狙う意味が無いもの**だけ——蟲の群れ、ナノ蟲など。

## 装備と調達

装備はクラスが作成時に配って終わり、ではありません。買って、売って、持ち替えられます。

| スロット | 中身 |
| --- | --- |
| 近接 / 遠隔 | 武器を一本ずつ。持ち替えると攻撃の選択肢が変わる |
| 防具 / 盾 | 着替えると AC が動く |

- 買ったものは持ち物に入り、**持っているものしか装備できません**
- 装備すると、今つけていたものは持ち物に戻ります（品物は増えも減りもしない）
- 売値は定価の 50%

**店が開くのは冒険の外だけ**です。パーティ編成とセッション支援では買えますが、
洞窟の中では買えません——開くと緊張が消えるので。持ち替えはいつでもできます。

## 名前の点検

ビルドもリンタも無い構成なので、`button(...)` を import せずに書いても何も
言われません。そのコードが実際に走るまで、つまり**プレイヤーがそのボタンを
押すまで** ReferenceError は出てきません。実際にそれで一度、キャラクターシートが
開かなくなりました。

```bash
npm run lint            # 呼ばれている名前が、どこかで定義されているか
```

`npm test` の頭で自動的に走ります。構文解析はせず、束縛されうる場所に現れた
名前を集めて照合するだけの素朴な作りです。取りこぼしはありますが誤検知はほぼ
出ません——この用途ではそのほうが役に立ちます。

## シナリオの健康診断

書いている最中には分からないことがあります。実際の長さ、結末の偏り、そもそも到達しない結末。
`npm run playtest` は 2 種類のボットで各シナリオを何十回も自動プレイし、それを数字にします。

```bash
npm run playtest                    # 収録シナリオ全部を一覧で
npm run playtest -- rain-check      # 1本を詳しく（技能別の成功率まで）
npm run playtest -- --runs=200      # 試行回数を増やす
npm run playtest -- --strict        # 問題があれば終了コード1（CI用）
```

ボットは 2 種類です。ランダムだけだと悲観側に、賢いボットだけだと楽観側に偏るため、
**両方の数字を「幅」として読みます**。

| ボット | 動き方 | 何を表すか |
| --- | --- | --- |
| **無作為** | 選べるものから一様に選ぶ。逃走もアイテムも使う | 行き当たりばったりの初回プレイ |
| **熟考** | 未見の場面を優先し、得意な技能の判定を選ぶ | 二周目、意図を持って進むプレイ |

報告される項目：手数の範囲、**場面到達率**（1回のプレイで全場面の何%が読まれるか）、
判定の成功率（技能別）、戦闘の回数と決着ラウンド、死者数、結末の分布。

自動で指摘される問題：

- **✗ 書いたのに一度も到達しない結末／場面** — 労力をかけて書いたのに存在しないのと同じ
- **✗ 選択肢が尽きて詰む** — 明確なバグ。ユニットテストでも止めています
- **⚠ 出口が開かないまま巡回し続ける** — ハブに「条件を満たせなくても進める道」が要る
- **⚠ 結末が一つに偏る** — 分岐が機能していない
- **⚠ 判定の成功率が極端** — DC が高すぎる／低すぎる
- **⚠ 場面到達率が低い** — 書いた分がプレイヤーに届いていない

### シナリオを書く手順

構造を先に固め、文章は最後に書きます。逆にすると、構造を直すたびに書き直しになります。

```bash
npm run new -- rooftop-deal --shape=hub --world=neon --title="屋上の取引"
npm run sync                      # 収録一覧とオフライン先読みを更新
npm run playtest -- rooftop-deal  # 長さと分岐を測る
```

1. **骨組みを出す** — `npm run new` で型を選ぶ。白紙から 30 ノードを手書きしない
2. **TODO を埋める**（本文は仮でよい）。あらすじと結末を先に決める。結末は 3 つ以上、開放条件に AND を重ねすぎない
3. **`npm run sync`** — 収録一覧と `sw.js` の先読みを生成する。手で書くと必ず漏れる
4. **工房の「点検」**を通す — リンク切れ・行き止まりが消えるまで
5. **`npm run playtest`** で長さと分岐を調整する
6. ここで初めて**文章を書く**

骨組みの型は 4 つ。9 本書いてこの 4 つに収束しました。両世界とも 4 つ揃っています。

| 型 | 構造 | 例 |
| --- | --- | --- |
| `linear` | 一本道。判定と戦闘を一度ずつ | はじめての依頼、初日の運び屋 |
| `hub` | 拠点から複数の調査先、手がかりが揃うと次へ | 鐘の鳴らない村、雨の領収書、硝子の果樹園 |
| `clock` | 変数が上限に達すると場面が強制的に変わる | 三分間の停電、潮の骨 |
| `route` | 複数の道のうち二区間を通って目的地へ | 最終便、三つの峠 |

`hub` と `route` の骨組みには、**条件が揃わなくても進める道**が最初から入っています。
これが無いと、拠点から出られなくなる詰みが生まれます（実際に作りました）。

`hub` では逆に、**「切り上げる」を拠点ノードだけに置く**のが大事でした。戻り先のノードにも
毎回置くと、一つ二つ調べただけで結末に着いてしまい、書いた場面の半分が読まれません。

## 開発

```bash
npm start          # ローカルサーバー
npm test           # ユニットテスト132件（ダイス・ルール・戦闘・シナリオ／エンジン・世界観）
npm run smoke      # 実ブラウザで3モードと2世界を通しで操作（25項目・要 npm install）
npm run playtest   # シナリオを自動で何十回も遊んで健康診断（下記）
npm run new        # シナリオの骨組みを作る（型を選ぶ）
npm run sync       # 収録一覧と sw.js の先読みを生成
npm run build      # www/ に配信用ファイルを出力
npm run icons      # アイコンを再生成
```

`main` に push すると GitHub Pages へ自動デプロイされます（`.github/workflows/deploy-pages.yml`）。
